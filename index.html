Rules We Follow

  1. Linux-first mindset — most infrastructure runs on Linux, so we reason about systems the way they actually behave, not through a GUI.
  2. Mock or local infrastructure before cloud — every concept is proven on a local Docker or Kind/Minikube cluster before it ever touches a paid cloud resource.
  3. One session equals one small slice equals one commit — no session bundles unrelated changes.
  4. Code and configuration must stay beginner-readable — no clever one-liners that trade clarity for brevity.
  5. Score below 80% on a quiz means repeat the lesson before moving on.
  6. Never jump ahead — concepts are taught in strict dependency order across layers.
  7. Always understand a tool's raw form (plain manifests, plain CLI) before adopting the abstraction that wraps it (Helm, Terraform).
  8. Every session ends with the same shape: concept, lab, commit, review — so progress is always inspectable in git history.
  9. Secrets and credentials never get committed — they are referenced, generated, or mocked, never hardcoded into tracked files.
  10. Prefer understanding the failure mode over memorizing the happy path — labs include predict-then-observe steps for exactly this reason.
  11. Every changed file gets reviewed before it is considered part of the session.
  12. The capstone is not a new curriculum — it is the same fundamentals, applied once, end-to-end, on one real application.
