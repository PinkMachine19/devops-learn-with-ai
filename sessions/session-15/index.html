Layer 6 Session 15 Observability & Landscape

The DevOps Language Landscape

Fourteen sessions in, you have typed Bash one-liners, written YAML for Kubernetes and GitHub Actions, and touched HCL in Terraform — without ever stopping to ask why those particular languages showed up where they did. This session has no lab and no commit. It steps back and maps the tools you already used, plus a few you have only heard of, so the next time you reach for a language you are choosing it on purpose instead of by habit.

Estimated time: 20–30 minutes · Flow: Pre-quiz → Concept → Discussion → Post-quiz
This is a discussion session, not a build session. There is no lab, no files change, and no commit checkpoint — read the concept, work through the discussion questions, and take the quizzes.

Answer before reading the concept. Need 4/5 to proceed.

Question 1 of 5

Why does nearly every DevOps toolchain lean on Bash somewhere?

Bash's advantage is availability, not raw power — it is present on virtually every Linux box already, so scripts written in it run anywhere without installing anything extra.
Question 2 of 5

What is a defining trait of Go that made Kubernetes, Terraform, and Prometheus all get written in it?

Go's compiled binaries, strong typing, and native concurrency support are exactly what infrastructure tools that need to be fast and reliable across platforms tend to need.
Question 3 of 5

What makes YAML, JSON, and HCL different from languages like Python or Go?

A Terraform .tf file or Kubernetes manifest describes what should exist, not a sequence of commands to run — a separate tool reconciles reality to match that description.
Question 4 of 5

Where are Perl, Awk, and Sed most likely to still show up today?

These tools predate widespread Bash scripting and mostly persist today in legacy log-processing pipelines that nobody has rewritten yet.
Question 5 of 5

Why did Ruby's role in infrastructure automation (Chef) shrink over time?

As tooling shifted toward plain YAML for describing desired state, Chef's Ruby-based DSL became less common relative to newer YAML-first tools.

3. The Concept — Reading the Landscape

Bash: the universal glue

Every Linux server ships with Bash, which is exactly why it is the default choice for entrypoint scripts, provisioning steps, and small CI/CD jobs. It is not a general-purpose application language — it is built to chain existing commands together and handle their text output. 

#!/bin/bash
# Loop through all running pods and print names
for pod in $(kubectl get pods -o name); do
  echo "Pod: $pod"
done

Python: readable, and enormous library support

Python's combination of readable syntax and a huge ecosystem of libraries is why it underpins tools like Ansible and the AWS CLI, and why it is a common choice for API automation and testing. 

import os
print("Home directory:", os.getenv("HOME"))

# Check web endpoint health
import requests
r = requests.get("https://api.github.com")
print("Status:", r.status_code)

Go: the language behind your tools

Go compiles to a single, fast, statically typed binary with concurrency built in and no separate runtime to install. That is the exact profile that made it the language of choice for Kubernetes, Terraform, and Prometheus — three tools this course already leans on heavily. 

package main

import "fmt"

func main() {
  fmt.Println("Hello from Go — the language behind K8s and Terraform")
}

YAML / JSON / HCL: declarative, not imperative

These are data formats, not programming languages. A Helm values file, a GitHub Actions workflow, and a Terraform configuration all describe a desired end state — replica counts, image tags, resource definitions — and a separate tool reconciles the real world against that description. 

# values.yaml — Helm chart config
app:
  name: diner
  replicas: 3
  image: diner:v2

Legacy text tools: read more than you write

Perl, Awk, and Sed predate Bash-centric scripting and still appear in older infrastructure for fast text processing on raw logs. Most engineers today encounter them when inheriting an old script, not when starting something new. 

# Extract lines with ERROR and print the 5th field
awk '/ERROR/ {print $5}' /var/log/syslog

Ruby and Chef: declarative before YAML won

Chef recipes, written in a Ruby-based domain-specific language, were an early attempt at declarative infrastructure — install this package, ensure this state — before YAML-first tools like Ansible became the dominant way to express the same idea. 

puts "Chef style resource example:"
package "nginx" do
  action :install
end
The pattern across all six: pick the tool by what the task actually needs — chaining commands, general-purpose logic, or declaring state — not by which one you already know best.

8. Post-Coding Quiz

Question 1 of 5

A teammate wants to write a quick script that restarts a container if a health check fails. What's the strongest argument for Bash here over Python?

When a task is essentially "run this command, check its result, run another command," Bash's zero-install availability and command-chaining strength usually win over reaching for a full language.
Question 2 of 5

Why is a Terraform .tf file described as declarative rather than imperative?

The defining trait of a declarative format is describing the desired end state rather than a sequence of steps — Terraform's own engine works out the plan to reach that state.
Question 3 of 5

You inherit an old log-processing script written in Awk. What is the most realistic response?

Legacy tools like Perl, Awk, and Sed are a "read more than write" category — the realistic skill is being able to understand what an inherited script does, not necessarily authoring new ones.
Question 4 of 5

What replaced most of Ruby/Chef's role in new infrastructure-as-code projects?

As the ecosystem moved toward plain YAML for expressing desired state, Chef's Ruby DSL became a smaller share of new infrastructure-as-code work.

10. What Breaks If This Knowledge Is Missing?

  • Reaching for Bash on a task that needs real logic: A script that grows past a few dozen lines of Bash conditionals becomes fragile and hard to debug — that is usually the sign a task has outgrown "glue" territory and belongs in Python or Go.
  • Treating YAML like a programming language: Someone who expects to write a loop or a conditional directly in a Kubernetes manifest will get stuck — declarative formats intentionally do not support that, by design.
  • Not recognizing Go in the toolchain: An engineer who does not know Kubernetes and Terraform are Go binaries under the hood will struggle to read their source, understand plugin systems, or contribute upstream fixes.
  • Panicking at inherited Perl/Awk/Sed: Assuming legacy scripts are unreadable garbage, rather than learning to read them, means re-solving already-solved problems and losing institutional knowledge baked into the original script.

11. What We Learned

Today you learned: Bash is the universal glue language on Linux, Python trades some speed for readability and library support, Go's compiled-and-concurrent design is why core infrastructure tools are written in it, YAML/JSON/HCL are declarative formats describing state rather than steps, and Perl/Awk/Sed and Ruby/Chef are legacy tools worth reading but rarely worth writing new.
