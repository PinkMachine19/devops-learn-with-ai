22-Session Curriculum

Sessions must be completed in order. Each layer unlocks only after the previous layer's final quiz scores ≥ 80%. A session is not complete until the commit is made and reviewed.

All sessions are open. Browse any session from the Sessions page. Layer gate quizzes remain recommended self-checks before advancing the lab track.
Active Layer 1 — Docker Foundations

Every later layer assumes fluency with containers. We start with the container lifecycle and storage model before touching orchestration of any kind.

#TitleCore ConceptProject MilestoneStatus
01 Container Lifecycle, Bind Mounts, Volumes, and Networks Images vs containers, run/stop/rm, bind mounts vs named volumes, bridge networks Run, inspect, and persist data through a single container Current
02 Multi-Container Apps with Docker Compose Compose services, networks, volumes, environment variables, service discovery by name Run a PHP + MySQL app with one docker compose up Gate
Layer 1 Gate: Recommended self-check — score ≥ 80% on Session 02's quiz before starting Layer 2.
Open Layer 2 — Kubernetes Basics

Kubernetes automates what Compose does by hand on one host, across many. We build a first Deployment before layering on namespaces, quotas, and configuration objects.

#TitleCore ConceptProject MilestoneStatus
03 Deployments, Services, Scaling, Rolling Updates, and Rollback Deployment/ReplicaSet/Pod hierarchy, Services, scaling, rolling updates, undo Deploy, scale, update, and roll back one app on a local cluster Available
04 Namespaces and Resource Quotas Logical isolation, ResourceQuota, LimitRange, per-namespace defaults Split workloads across namespaces with enforced quotas Available
05 ConfigMaps and Secrets Externalizing config, env injection vs volume mounts, Secret encoding vs encryption Move hardcoded config and credentials out of a Deployment Gate
Layer 2 Gate: Recommended self-check — score ≥ 80% on Session 05's quiz before starting Layer 3.
Open Layer 3 — Packaging & Infrastructure as Code

Raw manifests don't scale to real teams. Helm packages Kubernetes YAML; Terraform packages infrastructure itself, including the cluster resources Helm deploys into.

#TitleCore ConceptProject MilestoneStatus
06 Packaging Applications with Helm Charts, values.yaml, templating, releases, upgrade/rollback Convert the raw manifests from Layer 2 into a Helm chart Available
07 Terraform Fundamentals Providers, resources, state, plan/apply, declarative vs imperative Provision a local resource set with a Terraform plan and apply Available
08 Terraform with Kubernetes and Helm Providers kubernetes and helm Terraform providers, managing releases as code Deploy the Session 06 Helm chart entirely from Terraform Gate
Layer 3 Gate: Recommended self-check — score ≥ 80% on Session 08's quiz before starting Layer 4.
Open Layer 4 — Ingress & TLS

Services alone don't give you clean external URLs or HTTPS. Ingress and cert-manager solve routing and certificates the same way regardless of which packaging tool wrote them.

#TitleCore ConceptProject MilestoneStatus
09 Ingress Routing (Raw Kubernetes, Helm, and Terraform) Ingress controller vs Ingress resource, host/path rules, the same routing expressed three ways Route one hostname to the app using raw YAML, then Helm, then Terraform Available
10 TLS with cert-manager Certificate issuers, ClusterIssuer, automatic renewal, TLS secrets Serve the app over HTTPS with a cert-manager-issued certificate Gate
Layer 4 Gate: Recommended self-check — score ≥ 80% on Session 10's quiz before starting Layer 5.
Open Layer 5 — Release Strategies

Shipping new code safely is its own discipline. We cover blue-green and canary releases, plus the health checks and autoscaling that make either strategy safe.

#TitleCore ConceptProject MilestoneStatus
11 Blue-Green Deployments (Raw Kubernetes, Helm, and Terraform) Parallel environments, instant traffic cutover, instant rollback Cut traffic between a blue and green version with zero downtime Available
12 Health Probes and Autoscaling Liveness/readiness/startup probes, HorizontalPodAutoscaler, self-healing feedback loops Add probes and an HPA that reacts to load automatically Available
13 Canary Deployments (Raw Kubernetes, Helm, and Terraform) Gradual traffic shifting, weighted routing, blast-radius reduction Shift 10% then 100% of traffic to a new version safely Gate
Layer 5 Gate: Recommended self-check — score ≥ 80% on Session 13's quiz before starting Layer 6.
Open Layer 6 — Observability & Landscape

You cannot operate what you cannot see. We add metrics and dashboards, then step back for a discussion-only session mapping the wider DevOps tool landscape.

#TitleCore ConceptProject MilestoneStatus
14 Observability with Prometheus and Grafana Metrics scraping, PromQL basics, dashboards, alerting fundamentals Install Prometheus + Grafana and build one dashboard for the app Available
15 The DevOps Language Landscape Where each tool sits (build, package, provision, deploy, observe), how they compare Discussion only — no lab, no commit Gate
Layer 6 Gate: Recommended self-check — score ≥ 80% on Session 15's quiz before starting the Capstone.
Open Layer 7 — Capstone: Ship a Real App

Every earlier layer was a rehearsal. Now we build one real application — the Text Masker — and carry it through CI, CD to Docker, CD to Kubernetes, CD to the cloud, and both release strategies from Layer 5, for real.

#TitleCore ConceptProject MilestoneStatus
16 Capstone: Building the Text Masker App App architecture, containerizing a real service, Dockerfile design A running Text Masker app with a Dockerfile Available
17 Capstone: CI Pipeline with GitHub Actions Workflow triggers, jobs/steps, build + test automation A GitHub Actions workflow that builds and tests on every push Available
18 Capstone: CD to Local Docker Continuous delivery to a local Docker target, image publishing Pipeline deploys the built image to a local Docker host Available
19 Capstone: CD to Local Kubernetes Deploying pipeline artifacts into a local cluster Pipeline deploys the app to a local Kubernetes cluster Available
20 Capstone: CD to Cloud Kubernetes Cloud-managed Kubernetes (AKS/EKS/GKE), cluster credentials in CI Pipeline deploys the app to a managed cloud cluster Available
21 Capstone: Blue-Green Deployment for the Real App Applying Layer 5's blue-green pattern to a real pipeline Blue-green cutover for the Text Masker app in the cloud Available
22 Capstone: Canary Deployment for the Real App Applying Layer 5's canary pattern to a real pipeline Weighted canary rollout for the Text Masker app in the cloud Capstone
Capstone complete: By Session 22 one real application has been built, containerized, tested, deployed to local Docker, local Kubernetes, and a cloud cluster, then released twice — once blue-green, once canary — using the exact same tools taught in Layers 1–6.
